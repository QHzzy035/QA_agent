# RAG 检索增强生成

## 大模型的两个固有短板

大语言模型的知识来自训练数据，这带来两个问题：

**一是知识截止。** 模型的参数在训练完成后就冻结了，此后发生的事情它一概不知。问它上周的新闻，它要么说不知道，要么一本正经地编一个。

**二是无法访问私有数据。** 公司内部的文档、个人的笔记、项目的技术方案，这些内容从未出现在训练语料里，模型不可能知道。

## RAG 的基本思路

检索增强生成（Retrieval-Augmented Generation）的做法很直接：**回答之前先去查资料，把查到的内容连同问题一起交给模型。**

流程分为三步：

1. **索引**：把文档切成小段（chunk），用嵌入模型把每段转成向量，存进向量数据库。
2. **检索**：用户提问时，把问题也转成向量，在库里找出最相似的若干段。
3. **生成**：把检索到的段落作为上下文，和问题一起送进模型，让它基于这些材料作答。

## 为什么能缓解幻觉

关键在于模型被要求「基于给定材料回答」。材料是真实存在的原文，模型只需做理解和归纳，不必依赖可能出错的参数记忆。

工程上通常还会加一条约束：如果材料里找不到答案，就明确说明情况，而不是硬编一个。这一条对可信度的影响，往往比换更强的模型还大。

## 与传统搜索的区别

传统关键词搜索依赖字面匹配，用户问「怎么把文档变成模型能读懂的形式」，而文档里写的是「文本向量化」，字面上没有任何重合，搜索就会落空。

向量检索比较的是语义。只要两句话意思接近，向量距离就小，即使一个词都对不上也能召回。这是 RAG 相比传统搜索最本质的改进。

## 局限

RAG 不是万能的。检索环节一旦失败——该召回的资料没被找出来——后续生成再强也无力回天。因此**检索质量是 RAG 系统的天花板**，值得单独投入去做评测和调优。
