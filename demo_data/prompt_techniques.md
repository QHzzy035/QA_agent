# 提示词工程常用技巧

## 思维链

让模型「一步一步想」能显著提升推理类任务的准确率。原理不复杂：模型是逐 token 生成的，如果直接要求给出答案，它必须在一次前向计算里完成全部推理；而先输出中间步骤，相当于把推理过程外化成了后续生成的上下文，每一步都能基于前面已写出的内容继续。

实践中常见两种形式：

- **零样本思维链**：在提示词末尾加一句「请一步步分析」。
- **少样本思维链**：给几个带有完整推理过程的示例，模型会模仿这种格式。

需要注意的是，思维链对纯记忆类问题帮助不大，甚至可能引入不必要的错误。它更适合数学、逻辑、多步推理场景。

## 角色设定

在系统提示词里指定身份（如「你是一名资深的法律顾问」）会改变输出的措辞风格和关注重点。但它的作用常被高估——角色设定改变不了模型的知识边界，只是调整了表达倾向。指望靠一句「你是世界顶级专家」提升准确率，通常没有效果。

## 结构化输出

要求模型以特定格式（JSON、Markdown 表格、固定字段列表）返回，能大幅降低后续解析的成本。要点是：

1. 明确给出格式示例，而不只是描述格式
2. 说明字段缺失时怎么处理
3. 需要严格 JSON 时，优先使用模型 API 提供的结构化输出能力，而不是靠提示词约束

## 上下文中材料的位置

有研究指出，长上下文里模型对**开头和结尾**的内容注意力更强，中间部分容易被忽略，这一现象被称为「迷失在中间」。

对 RAG 系统的启示是：检索到的关键材料如果必须放在长上下文中，应尽量前置，而不是堆在中间。

## 温度参数

温度控制采样的随机性。事实问答、代码生成这类任务应设低温度（0～0.3），保证输出稳定可复现；创意写作可以调高。做评测时务必固定温度为 0，否则同一份输入每次跑出的结果都不同，指标就没有可比性。
