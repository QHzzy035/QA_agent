# Docker 容器技术基础

## 容器和虚拟机的区别

两者都能提供隔离的运行环境，但实现层次不同。

**虚拟机**虚拟出的是一整套硬件，上面跑一个完整的操作系统内核，再在上面跑应用。一台宿主机上开十个虚拟机，就有十个独立内核，每个都要占用内存和启动时间。

**容器**共用宿主机的内核，只在进程层面做隔离（Linux 的 namespace 负责隔离视图，cgroup 负责限制资源）。容器里没有独立内核，启动时不需要引导操作系统。

结果就是：容器通常几百毫秒启动，虚拟机要几十秒；同一台机器上能跑的容器数量远多于虚拟机。

代价是隔离强度较弱。容器共享内核意味着一旦内核有提权漏洞，逃逸风险比虚拟机高。

## 镜像与容器

**镜像**是只读的模板，由一组分层（layer）叠加而成。**容器**是镜像的一个运行实例，启动时会在镜像之上加一个可写层。

分层带来的好处是复用：多个镜像共享相同的底层（比如都是同一个 Python 基础镜像），磁盘和网络传输都只存一份。改 Dockerfile 时，未发生变化的上层可以直接用缓存，这是构建速度的关键。

因此 Dockerfile 里指令的顺序很重要——**变化频率低的放前面**。典型做法是先复制依赖清单并安装依赖，最后才复制源代码，这样改代码不会导致重新安装依赖。

## 数据卷

容器被删除时，可写层的数据一并消失。需要持久化的数据（数据库文件、日志、上传的文件）必须挂载到容器之外：

- **绑定挂载**：把宿主机的某个目录直接挂进容器，适合开发时改代码即时生效。
- **数据卷**：由 Docker 管理，位置不透明但性能更好，适合生产环境的数据持久化。

## 网络

同一自定义网络中的容器可以通过**容器名**互相访问，Docker 内置了 DNS 解析。这是容器间通信的推荐方式——不要写死 IP，容器重启后 IP 会变。

默认的 bridge 网络不提供这种名称解析，需要手动 `--link`，而该选项已废弃，所以实践中应该自建网络。
